# 05 · 错误码与排查

本文按「HTTP 状态码 → 错误码 → 原因 → 处理」的顺序说明网关的报错。调用失败时先看这三处：

1. **HTTP 状态码**：400 / 401 / 404 / 429 / 5xx，先判断是请求问题、权限问题还是上游问题；
2. **响应 JSON 的 `error.code`**：比 `error.message` 稳定，客户端和脚本应按它判断；
3. **响应头 `X-Request-Id`**：形如 `req_ab12cd34ef56`，和面板「日志」里的 `#req_...` 对应；反馈问题时带上它。

```json
{
  "error": {
    "message": "model web-gemini-4-carbon-low is not available for this account",
    "type": "invalid_request_error",
    "code": "model_not_available"
  }
}
```

面板「日志」最多保留 30 条；一次 AI 请求成功时固定 3 条（`ai request` / `ai response` / `ai done` 或 `ai failed`），不记录提示词和回答正文。失败日志里同时有 `status`、`code`、`phase` 和请求 ID。

---

## 1. 按 HTTP 状态码

| 状态码 | 常见错误码 | 通常原因 | 怎么处理 |
|---|---|---|---|
| **400** | `invalid_messages`、`invalid_json`、`thinking_not_supported`、`thinking_not_available`、Cookie 格式/校验失败 | 请求体不合法；给 Auto 传了思维强度；模型不支持该强度；自定义 Key/密码不符合格式 | 检查 `messages` 是否非空数组；Auto 去掉 `@think` / `reasoning_effort`；从 `/v1/models` 的 `thinking_levels` 里选强度 |
| **401** | `invalid_api_key`、`session_expired`、`admin_unauthorized`、`bad_password` | API Key 错误或缺失；Gemini Cookie 失效；管理员未登录 | 换正确的 `Authorization: Bearer ...`；到「凭证」页重新导入 Cookie；重新登录面板 |
| **403** | 上游 403 | 出口 IP 被 Google 风控；账号无权限 | 重新导出完整 Cookie；换代理节点/等一段时间；不要在短时间高频请求；Cookie 被拒绝时重新导入 |
| **404** | `model_not_found`、`model_not_available`、`not_found` | 模型名拼错；模型不在当前账号的 picker；路径不存在 | 先 `GET /v1/models` 看真实列表；Pro 号没有 Carbon，请求会返回 404，这是预期行为 |
| **409** | `admin_password_env` | 部署时用 `ADMIN_PASSWORD` 环境变量固定了密码，面板里不能再改 | 去部署平台改环境变量，或删掉该变量后重启再用面板改 |
| **429** | `usage_rate_limited`、`bard_error`（`BardErrorInfo [7]`）、`pggo_rate_limited` | 账号或 IP 被限流；额度窗口打满；AI Studio 限流 | 等几分钟；换代理节点；增加账号；看面板额度 |
| **499** | 无固定 code | 客户端主动断开（网关内部使用） | 一般是客户端超时/取消，不是网关错误；调大客户端超时 |
| **500** | `internal_error`、`bad_model_spec`、`pggo_cookie_decrypt_failed` | 网关内部异常；模型目录数据不完整；`ENCRYPTION_KEY` 变了导致 Cookie 解不开 | 看日志里的堆栈/请求 ID；重新导入凭证；确认 `ENCRYPTION_KEY` 没换 |
| **502** | `upstream_failed`、`page_failed`、`session_expired`、`model_downgraded`、`model_unverified`、`catalog_unavailable`、`catalog_empty`、`catalog_parse_failed`、`pggo_transport_error`、`pggo_failed`、`usage_failed` | 上游返回错误；Cookie 失效；Google 静默降级/不报模型；目录拉取失败；AI Studio 不可达 | 看日志里的 `error=`；重新导入 Cookie；换节点；Carbon 降级说明账号没有对应权益 |
| **503** | `no_web_credential`、`no_pggo_credential`、`waa_disabled`、`waa_missing_binary` | 没有可用凭证；WAA 签名器被禁用/二进制缺失；账号目录为空 | 导入 Gemini/AI Studio Cookie；部署时不要设 `WAA_DISABLED=1`；重建镜像 |
| **504** | `waa_timeout`、上游超时 | AI Studio 签名器或上游长时间无响应 | 重试；检查代理；WAA 超时看容器资源 |

> 同一个 `code` 在不同路径下状态码可能略有差异（例如 `session_expired` 在目录请求里是 502，在额度接口里是 401）。以响应里的 `status` 和日志为准。

## 2. 常见 code 明细

### 模型与思维强度

| code | 含义 | 处理 |
|---|---|---|
| `model_not_found` | 模型名不在网关的路由里（拼写错误、旧 ID） | `GET /v1/models` 复制准确 ID |
| `model_not_available` | 模型不在**当前账号**的 picker 目录里 | 换账号或换模型；Pro 号请求 Carbon 就是这个 |
| `thinking_not_supported` | 该模型不支持思维强度（目前是 Gemini 4 Auto） | 去掉 `@think=`、`reasoning_effort`、`thinking.budget_tokens` |
| `thinking_not_available` | 该模型存在，但没有这个强度档位 | 用 `/v1/models` 的 `thinking_levels` |
| `model_downgraded` | 请求了显式模型，Google 实际返回了另一个（常见于无权益的 Carbon） | 说明账号没有该模型权益，换模型/升档；不要重试同一个模型 |
| `model_unverified` | 响应里没有服务端模型名，无法确认是否被降级 | 重试；持续出现就看上游协议是否变化 |
| `bad_model_spec` | 网关内部模型目录缺 hash/number | 到面板点「刷新目录」；仍失败看日志 |

### Cookie 与登录

| code | 含义 | 处理 |
|---|---|---|
| `invalid_api_key` | API Key 缺失或不在列表里 | 用面板创建的 Key；注意 `Bearer ` 前缀 |
| `session_expired` | Gemini 网页会话失效（302/401） | 重新导入 Cookie；多账号时删掉失效的那个 |
| `bad_cookie` / `cookie_rejected` / `cookie_no_sid` / `cookie_incomplete` | Cookie 不完整、没有 SID、被 Google 拒绝 | 用 Cookie-Editor 导出完整域；确认包含 `SID` 或 `__Secure-1PSID` |
| `page_failed` / `page_tokens_missing` | 打开 Gemini 页面失败或页面里没有 `at`/`bl` | 换节点；确认账号能正常打开 gemini.google.com；重新导入 |
| `oauthlogin_failed` / `merge_session_failed` | 主令牌换 Cookie 失败 | 重新授权/导入；检查账号是否被登出 |

### 上游与额度

| code | 含义 | 处理 |
|---|---|---|
| `upstream_failed` | StreamGenerate 返回非 200 | 看日志里的上游状态和摘要；换节点/重试 |
| `bard_error` | Google 返回 `BardErrorInfo` | `[7]` 通常是限流（429），等一会；其他编号按日志内容排查 |
| `catalog_unavailable` / `catalog_failed` / `catalog_parse_failed` / `catalog_empty` | 拉取账号模型目录失败/为空 | 检查网络和 Cookie；点「刷新目录」；多账号时确认至少一个可用 |
| `usage_failed` / `usage_parse_failed` / `usage_rate_limited` | 额度查询失败/解析失败/被限流 | 不影响聊天时忽略；持续失败重新导入 Cookie |
| `pggo_transport_error` / `pggo_failed` / `pggo_rate_limited` | AI Studio 网络错误/失败/限流 | 检查代理；等一会；确认 AI Studio Cookie 有效 |
| `waa_*` | AI Studio 的 WAA 签名器异常 | 看容器日志；确认镜像里有签名器；不要设 `WAA_DISABLED=1` |

### 管理端

| code | 含义 | 处理 |
|---|---|---|
| `admin_unauthorized` | 管理员未登录/会话过期 | 重新登录面板 |
| `bad_password` | 当前密码错误 | 重新输入；忘了就看部署平台的环境变量 |
| `weak_password` | 新密码少于 8 位或多于 128 位 | 换一个 8–128 位的密码 |
| `admin_password_env` | 密码由 `ADMIN_PASSWORD` 固定 | 改环境变量，或删掉后重启 |
| `invalid_messages` | `messages` 不是非空数组 | 按 OpenAI Chat Completions 格式传 |

## 3. 日志示例

成功：

```text
ai request  #req_ab12cd34ef56 model=web-gemini-4-neon-high stream=true messages=3
ai response #req_ab12cd34ef56 model=web-gemini-4-neon-high stream=true ms=812
ai done     #req_ab12cd34ef56 model=web-gemini-4-neon-high stream=true phase=response ms=5321 status=200 chars=184
```

失败：

```text
ai request  #req_12ab34cd56ef model=web-gemini-4-carbon-low stream=false messages=1
ai failed   #req_12ab34cd56ef model=web-gemini-4-carbon-low stream=false phase=request ms=903 status=404 code=model_not_available error=model web-gemini-4-carbon-low is not available for this account
```

- `phase=request`：请求还没拿到上游响应就失败（鉴权、目录、网络）；
- `phase=response`：已经收到响应，在流式过程中失败（断流、降级、上游错误）；
- `chars` 是已转发给客户端的正文字符数，不是 token 数，也不包含提示词。

## 4. 还是解决不了

带上这些信息反馈，能少一轮来回：

- 响应头 `X-Request-Id` 和响应 JSON 的 `error.code` / `error.message`；
- 面板「日志」里同一 `#req_...` 的 3 条记录（或失败记录）；
- 用的模型 ID、是否流式、是否走了代理；
- 是否刚换过 `ENCRYPTION_KEY` / Cookie / 部署环境。

Cookie 属于敏感凭据，反馈时不要贴完整 Cookie，只贴日志和错误码即可。
