# 原理：它是怎么把 Gemini 网页版变成 API 的

> 先看结论：这不是官方 API。它用你浏览器里的**登录 Cookie**，冒充“你本人打开了 gemini.google.com”，然后把网页版发消息的那套私有请求，翻译成 OpenAI 格式。

---

## 1. 两种“用 Gemini”的方式

| | 官方 API | 本项目（网页版通道） |
|---|---|---|
| 凭证 | `AIza...` API Key | 浏览器的 `Cookie`（SID / `__Secure-1PSID` …） |
| 计费 | 按 token 付费 | 走你账号的网页版额度（免费/Pro） |
| 协议 | 公开 REST | 私有 RPC：`/_/BardChatUi/data/.../StreamGenerate` |
| 稳定性 | 官方承诺 | 跟着网页版改版，随时可能坏 |
| 合规 | 允许 | 违反 Google 服务条款，有封号风险 |

本项目只实现第二种。

---

## 2. 一次请求的完整链路

```
客户端（OpenAI SDK / Cherry Studio / curl）
      │  POST /v1/chat/completions
      ▼
webg-gateway
      │  1. 选一个可用 Cookie（最久未用优先）
      │  2. GET https://gemini.google.com/app
      │        → 拿到 at（SNlM0e）和 bl（cfb2h）
      │  3. 把 OpenAI messages 拼成网页版 prompt
      │  4. POST .../StreamGenerate?bl=...&rt=c
      │        form: f.req=<JSON>&at=<at>
      ▼
gemini.google.com ──► Google 后端（按 mode 选模型）
      │  流式返回若干数据帧
      ▼
webg-gateway 解析帧、拼文本
      │  转成 OpenAI SSE
      ▼
客户端
```

### 2.1 登录态：Cookie 就是账号

浏览器登录 Google 后，`gemini.google.com` 会收到一组 Cookie，其中关键的是：

- `SID` / `__Secure-1PSID`、`__Secure-3PSID`：主会话
- `HSID`、`SSID`、`APISID`、`SAPISID`、`__Secure-1PAPISID`、`__Secure-3PAPISID`：辅助/跨域
- `NID` 等：其他用途

**只要拿到这组 Cookie，就等于拿到了这个账号的 Gemini 网页会话**，不需要密码、不需要 2FA。所以：

- 服务端用 `ENCRYPTION_KEY` 做 AES-256-GCM 加密后才落盘；
- 不要把 Cookie 发给不信任的网关；
- 退出登录 / 改密码会让 Cookie 立刻失效。

### 2.2 `at` 和 `bl` 是什么

打开 `gemini.google.com/app` 的 HTML 里藏着两个值：

- `SNlM0e` → `at`：本次会话的 CSRF token（约 42 字符）
- `cfb2h` → `bl`：前端构建号，例如 `boq_gemini-web-uiserver_20261119.05_p0`
- `FdrFJe` → `f.sid`：本实现里用不到

`at` 会过期，所以网关不缓存太久（默认 30 分钟重新抓一次，Cookie 缓存 6 小时）。

> 小坑：这个页面返回的响应头非常大，Node 默认 16KB 上限会报 `Parse Error: Header overflow`，所以代码里把 `maxHeaderSize` 调到了 128KB。

### 2.3 请求体：`f.req` 里的神秘数组

网页版发给 Google 的是一个 JSON 数组（内部叫 wire / inner），关键位置：

| 下标 | 含义 |
|---|---|
| `inner[0]` | `[prompt, 0, null, null, null, null, 0]` |
| `inner[1]` | `["zh-CN"]` 语言 |
| `inner[17]` | `[[thinkLevel]]` 思考等级 |
| `inner[41]` | `[2]` 保留历史 / `[1]` 临时会话 |
| `inner[45]` | `1` 表示临时（不进历史记录） |
| `inner[59]` | 随机 UUID |
| `inner[79]` | **mode**：模式编号 |
| `inner[80]` | **思维强度**：`1`=低 `2`=中 `3`=高；不传则用该档位默认值 |

外层再包一层：`[null, JSON.stringify(inner)]`，作为表单字段 `f.req` 发出去。

**mode 就是“模型选择器”**：

| mode | 网页端档位 | 本项目的模型 ID |
|---|---|---|
| 1 | 日常帮助 · 4 Hydrogen | `web-gemini-4-hydrogen-low\|medium\|high` |
| 2 | 更深入的分析 · 4 Neon | `web-gemini-4-neon-low\|medium\|high` |
| 3 | 代码和复杂工作 · 4 Carbon | `web-gemini-4-carbon-low\|medium\|high` |
| 4 | 自动 | `web-gemini-4-auto-low\|medium\|high` |
| 6 | 轻量/快速 | `web-gemini-4-flash-lite-low\|medium\|high` |

注意：**网页端没有公开“模型列表”接口**。所以网关的“动态探测”不是读列表，而是拿你的 Cookie 给每个 mode 真发一句 `ping`，能回就算可用。

### 2.4 响应：流式帧怎么读

`StreamGenerate` 返回的是一行行 `wrb.fr` 数据，内容是嵌套数组。网关会：

1. 逐行剥掉 `)]}'`、长度前缀等包装；
2. 解析 JSON；
3. 从 `chunk[0][0][0]` 里取 `parts`，`part[1]` 是正文，`part[10]` 表示“这是思考过程”；
4. 文本是**增量**的，需要拼接；
5. 再转成 OpenAI 的 `data: {"choices":[{"delta":...}]}`。

## 3. 为什么要代理池

Google 会对“机房 IP + 高频请求”弹人机验证：

```
302 → https://www.google.com/sorry/index?continue=https://gemini.google.com/app
```

这不是 Cookie 的问题——换一个完全无效的 Cookie 也一样 302。解决办法只有换出口 IP：

- 一个可用的 HTTP 代理：设 `WEB_PROXY`；
- 或者用面板里的「代理池」：导入 Clash 订阅，内置 mihomo 在服务端拉起多节点，命中 `/sorry` 自动换节点重试。

代理池还能每 10 分钟自动测速并切到最快节点（`AUTO_FASTEST`）。

---

## 4. 多账号轮换

凭证池里每条 Cookie 都有 `uses`、`lastUsedAt`、`lastError`：

- 新请求优先选**最久没用**的那条；
- 请求成功 `uses + 1`；
- 失败标记 `lastError`，并按错误类型冷却（429 冷却 60 秒，其他 30 秒起）。

这样多个账号会自然均摊，不会把一个号薅到风控。

## 5. 数据存在哪

| 数据 | 位置 | 说明 |
|---|---|---|
| 凭证（加密 Cookie） | `DATA_DIR/credentials.json` | AES-256-GCM，格式 `enc:v1:iv:tag:ct` |
| API Keys | `DATA_DIR/api-keys.json` | 只存 SHA-256 哈希，明文只在创建时展示一次 |
| 管理员 | `DATA_DIR/admin.json` | scrypt 哈希 |
| 设置 | `DATA_DIR/settings.json` | 代理订阅、删除的节点等 |
| 加密密钥 | `ENCRYPTION_KEY` 环境变量或 `DATA_DIR/secret.key` | 换掉它 = 旧密文全部解不开 |

Render 免费层的磁盘是**临时的**：重新部署/休眠唤醒后会清空。所以推荐接 Cloudflare KV：

- 启动时先读本地，再读 KV；KV 有数据就以 KV 为准；
- KV 为空就把本地迁移上去；
- 之后的写操作防抖合并后写入 KV；
- 读取失败的记录**不会**被内存默认值覆盖（避免把订阅配置冲掉）。

---

## 6. 安全与风险（务必读）

1. **Cookie 等于账号**：泄露 = 别人可以读你的 Gemini 对话历史、以你的身份发消息。只部署在自己控制的机器上。
2. **违反 ToS**：Google 明确禁止把网页版/客户端会话用于第三方 API 转售或自动化。已有封号案例。
3. **不要公开分享**：别把带 `/admin/` 的地址和密码发到群里；不要提交 `.env`、`data/`。
4. **API Key 也是钥匙**：泄露后别人可以消耗你的账号额度，可在面板随时删除重建。
5. **合规使用**：个人自用、低频、不转售，风险相对低；批量/商用请走官方 Gemini API。
