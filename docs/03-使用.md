# 使用手册：从 Cookie 到调通第一个请求

---

## 1. 拿到 Gemini 网页版 Cookie

> 关键：要的是 **`gemini.google.com` 的 Cookie**，不是 `aistudio.google.com`，也不是 Google 账号页面的 Cookie。

### 步骤

1. 打开一个**无痕窗口**（避免污染主浏览器会话，也方便随时退出）。
2. 访问 <https://gemini.google.com>，用你的 Google 账号登录。
3. 随便发一句话，确认能正常回复。
4. 按 `F12` 打开开发者工具 → **Network（网络）** 标签。
5. 在页面里再发一句话，列表里会出现一个 `StreamGenerate?bl=...` 的请求（没有的话刷新页面再发）。
6. 点这个请求 → **Headers** → 拉到 **Request Headers** → 找到 **`Cookie`**。
7. 右键 → **Copy value**（或全选复制整行 `Cookie: ...` 后面的内容）。

得到的字符串长这样（很长，一行）：

```
SID=g.a000...; __Secure-1PSID=g.a000...; __Secure-3PSID=g.a000...; HSID=...; SSID=...; APISID=...; SAPISID=...; __Secure-1PAPISID=...; __Secure-3PAPISID=...; NID=...; ...
```

### 用 Cookie-Editor 插件（更省事）

1. 安装 **Cookie-Editor**（Chrome/Edge 商店）。
2. 在 `gemini.google.com` 页面点插件图标 → **Export** → 选 **Header String**。
3. 复制得到的一整串 `k=v; k=v; ...`。

### 不要用 `document.cookie`

`SID`、`__Secure-1PSID` 都是 `HttpOnly`，JS 读不到。Console 里 `document.cookie` 拿到的只是残缺的一半，导入必然失败。

### Cookie 的有效期

- 正常使用：几小时到几天；
- 退出登录、改密码、清理浏览器数据：立即失效；
- 失效后重新按上面步骤导一次即可。

> 一个账号可以只保留一条凭证；多条同账号不会更快，只会重复轮换。

## 2. 导入到面板

1. 打开 `https://<你的地址>/admin/`，登录。
2. 「凭证」tab → 找到 **Gemini 网页版 Cookie** 卡片。
3. 填写：
   - **邮箱**：建议填，方便区分（比如 `abc@gmail.com`）；
   - **Cookie**：粘贴整串；
   - **备注**：随便，比如 `主号`。
4. 点 **验证并导入**。

网关会先拿这串 Cookie 请求一次 `gemini.google.com/app`：

- 成功：凭证池出现一条 `cookie / active`，并显示邮箱；
- 失败：直接报错（`Cookie 验证失败：…`），不会存垃圾数据。

**导入后点「测试」**：显示“会话有效”就稳了；显示 `302 /sorry` 的话是 IP 被风控，看第 5 节。

### 多账号

重复上面的步骤，每个账号导入一条。网关会按“最久未用”轮换，自动均摊。

### AI Studio 账号（`pggo-*`）

网页版和 AI Studio 是两条独立通道，可以只导其中一条，也可以都导：

1. 无痕窗口登录 <https://aistudio.google.com/>；
2. DevTools → Network → 选一个 `GenerateContent` 请求 → 复制整段 `Cookie`（或 Cookie-Editor 导出 Header String）；
3. 面板「凭证」→ **AI Studio Cookie** 卡片 → 填邮箱（可选）、Cookie、备注 → **验证并导入**。

导入时服务端会请求 `ListModels` + `GetAiStudioBenefitTier`：

- 会校验 Cookie 是否真的登录（垃圾 Cookie 会 400，不会被存下来）；
- 会读出这个账号的档位（Free / Pro / Ultra）和**实际可用的模型清单**；
- `/v1/models` 里随后会多出 `pggo-<上游模型>` 条目，例如 `pggo-gemini-4-neon`。

AI Studio 通道走 MakerSuite 私有 RPC，需要一个 WAA（BotGuard）签名器：Docker 镜像自带；本地跑要设置 `WAA_SIGNER_PATH` 指向 `waa-signer` 二进制。

延迟与限流：

- 第一次调用要冷启动签名器（约 5–10 秒），再叠加模型思考时间，单次可能要 30–100 秒；之后热启动会快很多。
- `503 This model is currently experiencing high demand` 是 Google 侧对该账号/该模型的临时限流，换模型或过一会儿再试；`pggo-gemini-3.6-flash` 在高峰期经常 503。
- Cookie 过期会返回 `pggo_session_expired` 或 `waa_session_expired`，重新从 `aistudio.google.com` 复制即可。
- **慢模型请用流式**（`"stream": true`）：Render 的代理会在连接长时间静默后断开，非流式请求大约 100 秒还没返回就会被切断；流式会定期发送心跳，能一直等到模型出字。

## 3. 模型

网页版模型按账号真实目录生成，不再固定 15 个。一个典型 Pro 号会看到 7 个：

| 网页端模型 | 模型 ID | 思维强度 |
|---|---|---|
| 自动 | `web-gemini-4-auto` | 无（由 Google 路由，单 ID） |
| 4 Hydrogen | `web-gemini-4-hydrogen-low` / `-medium` / `-high` | 三档 |
| 4 Neon | `web-gemini-4-neon-low` / `-medium` / `-high` | 三档 |
| 4 Carbon | `web-gemini-4-carbon-low` / `-medium` / `-high` | 三档（仅 Ultra 账号的 picker 会出现） |

- Auto 没有思维强度；对 Auto 传 `reasoning_effort` / `@think` 会返回 `400 thinking_not_supported`。
- 不带强度的 bare ID（`web-gemini-4-neon` 等）仍然可用，等于该模型的 `low`。
- 旧 ID（`web-gemini-3.7-flash` 等）**已删除**，用旧名会 404。
- 具体“这个账号到底有哪些”以面板「模型 → 刷新目录」为准；结果同步到 `/v1/models`。Pro 号请求 Carbon 会返回 `404 model_not_available`，不会静默降级。

### 思维强度（low / medium / high）

档位决定「用哪个模型」，思维强度决定「想多久」。三档含义：

| 强度 | 行为 | 适合 |
|---|---|---|
| `low` | 想得最少、最快 | 事实问答、改写、翻译 |
| `medium` | 折中 | 一般推理、长文 |
| `high` | 想得最深、最慢，输出 token 也最多 | 难题、代码、数学 |

**首选：直接选带强度的模型 ID**，例如 `web-gemini-4-neon-high`。这样接 AI 的客户端（只能填模型名、没有 `reasoning_effort` 开关）也能挑强度。

兼容方式（给能发请求字段的客户端）：

1. `"model": "web-gemini-4-neon"` + `"reasoning_effort": "high"`（也认 `reasoning.effort`；Claude 风格的 `thinking.budget_tokens` 会折算：<2048=low，<4096=medium，≥4096=high）。
2. 模型名后缀：`"model": "web-gemini-4-neon@think=high"`。

优先级：`@think` 后缀 > 请求字段 > 模型名里的强度；三者都没有时用 bare ID 的默认 `low`。Auto 固定 `inner[80]=0`，不接受强度。思维强度只对 `web-*` 模型生效；`pggo-*`（AI Studio）走 `thinkingConfig`，同样认 `reasoning_effort`。

> 强度越高越慢，`high` 在长思考题上可能多等几十秒；流式请求不受影响，非流式请留足超时。

### 怎么判断某个模型能不能用

面板「模型」页 → **刷新目录**。它会用你导入的 Cookie 调一次 `otAQ7b`，读取账号自己的模型选择器（picker），再生成 `/v1/models`：

```
web-gemini-4-auto              Auto
web-gemini-4-hydrogen-low      4 Hydrogen
web-gemini-4-hydrogen-medium   4 Hydrogen Medium
web-gemini-4-hydrogen-high     4 Hydrogen High
...
```

Carbon 不在列表里，说明当前账号没有 Carbon 权益；这不是“探测失败”，而是账号目录里就没有。

### 档位、额度与自动跳过

「凭证」表格的「档位」「额度」两列来自 Google 网页端自己的数据：

| 记法 | 含义 |
|---|---|
| Free | 免费号（没有订阅，或没检测到档位） |
| Plus / Pro / Ultra | Google AI 订阅档位（TIER0 / TIER1 / TIER2） |
| 5h | 五小时窗口的剩余额度 |
| 7d | 七天窗口的剩余额度 |

- 点「额度」按钮会立刻请求一次；平时聊天成功后每 10 分钟自动刷新。
- 进度条颜色：剩余 ≤30% 变黄，≤10% 变红；鼠标悬停可看重置时间。
- 某个账号额度耗尽（剩余 ≤0.5% 且还没重置）时，请求会自动跳过它、优先用其他账号；**所有**账号都耗尽才会回退到最早的账号（可能 429）。
- 「模型」页的「账号档位」列是当前账号的订阅标签，不是模型的硬性门槛；可用性以账号 picker 为准。

## 4. 创建 API Key 并调用

### 4.1 创建 key

面板「API Keys」→ 填备注 → 可选填自定义 Key（8-200 个可见 ASCII 字符；留空自动生成 `sk-webg-gateway-...`）→ **新建** → 点行内「复制」。

> Key 会保存在 `api-keys.json` 并在面板列出，随时可复制；请求校验用 SHA-256 哈希。
>
> 也可以用环境变量 `GATEWAY_API_KEYS=key1,key2` 预置（不落库）。

### 4.2 curl

```bash
curl https://<你的地址>/v1/chat/completions \
  -H "Authorization: Bearer sk-webg-gateway-你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "web-gemini-4-hydrogen",
    "messages": [
      {"role": "system", "content": "你是一个简洁的助手"},
      {"role": "user", "content": "用 3 句话介绍杭州"}
    ]
  }'
```

### 4.3 流式

```bash
curl -N https://<你的地址>/v1/chat/completions \
  -H "Authorization: Bearer sk-webg-gateway-你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "web-gemini-4-neon",
    "stream": true,
    "stream_options": {"include_usage": true},
    "messages": [{"role": "user", "content": "从 1 数到 20"}]
  }'
```

### 4.4 Python（openai 官方 SDK）

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://<你的地址>/v1",
    api_key="sk-webg-gateway-你的key",
)

resp = client.chat.completions.create(
    model="web-gemini-4-hydrogen",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

### 4.5 Node.js

```js
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://<你的地址>/v1",
  apiKey: "sk-webg-gateway-你的key",
});

const stream = await client.chat.completions.create({
  model: "web-gemini-4-neon",
  stream: true,
  messages: [{ role: "user", content: "写一个冒泡排序" }],
});

for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content || "");
}
```

### 4.6 常见客户端

| 客户端 | 填法 |
|---|---|
| **Cherry Studio** | 设置 → 模型服务 → OpenAI → API 地址填 `https://<你的地址>/v1`，密钥填 `sk-webg-gateway-...`，手动添加模型名 `web-gemini-4-hydrogen` 等 |
| **NextChat** | 设置 → 自定义接口 → 接口地址 `https://<你的地址>`（有的版本要求不带 `/v1`，试两次）→ 模型名手填 |
| **Open WebUI** | 设置 → Connections → OpenAI API → URL `https://<你的地址>/v1`，Key 填 `sk-webg-gateway-...` |
| **LobeChat** | 模型服务 → OpenAI → 代理地址 `https://<你的地址>/v1` |
| **Dify / FastGPT** | OpenAI 兼容供应商，Base URL `https://<你的地址>/v1` |

> 注意：Cherry Studio 等客户端可能会先请求 `/v1/models`，本网关返回当前账号 picker 里的模型（典型 Pro 号 7 个），正常。

## 5. 代理池（可选，但推荐）

如果你看到：

```
gemini page failed (302) -> https://www.google.com/sorry/index?continue=...
```

说明 Render 的出口 IP 被 Google 判为异常流量，**和 Cookie 无关**。

### 5.1 导入订阅

1. 准备一个 Clash 订阅链接（`https://.../sub?token=...` 或 `clash://install-config?url=...`）。
2. 面板「设置」→ 代理池 → 粘贴 → **导入并启动**。
3. 状态变成「● 运行中」，节点自动进入「默认分组」，下面出现节点列表。

### 5.2 默认分组与节点管理

导入后所有可用节点自动进入「默认分组」，节点列表上方会显示分组名和节点数。

- **删除全部节点**：一次清空默认分组并停止使用代理池；订阅 URL 仍保留，重新导入订阅即可恢复；
- **删除**：只移除默认分组下的某个节点；删除最后一个节点会清空分组并停止使用；停止状态下也可以删除，不会因此把代理池重新启动；
- **停止 / 启用**：停止只停止使用代理池 VPN，默认分组、节点和订阅都会保留；再点「启用」用已保存的订阅恢复，不必重新导入。停止状态会跨服务重启保留；
- **测速全部**：并发测全部节点，约 10 秒，显示延迟徽章（绿 <400ms / 黄 <900ms / 红）；
- **使用**：切到某个节点（停止状态下不可用）；
- **搜索**：节点多的时候过滤名字；
- **自动切最快节点**：在「自动切最快节点 ___ 分钟一次」里填 1–1440 的整数并保存，默认 10 分钟；间隔会持久化到设置。测速切节点时如果有 AI 回复还没结束，会先延后，等所有回复结束再重试，避免切换网络把流式响应打断；`AUTO_FASTEST=0` 可整体关闭（输入框会禁用）；
- 导入时会自动跳过订阅里常见的横幅节点（名字含“剩余流量 / 到期 / 官网 / 订阅 / 导航 / 时间戳”等），避免最快节点选到假节点。

### 5.3 单代理模式

不想用 mihomo，也可以只给一个 HTTP 代理：

```bash
WEB_PROXY=http://1.2.3.4:7890
```

## 6. 日志

面板「日志」tab 实时显示（内存 30 条，重启清空）：

- 每次 AI 请求成功时固定 3 条：`ai request`（发送）→ `ai response`（收到第一段响应）→ `ai done`（完成）；失败时第 3 条为 `ai failed`，在收到响应前就失败则只有 2 条；
- 每条都带请求 ID（`#req_...`）、模型、是否流式、耗时；失败还带 HTTP `status`、错误 `code` 和错误信息；
- 不记录提示词、消息内容和模型回答正文，只记录条数、字符数等元数据；
- Cookie 验证、`/sorry` 换节点、上游 4xx/5xx 等系统事件也在这 30 条里。

客户端的响应头里有 `X-Request-Id`，和日志里的 `#req_...` 对应，反馈问题时带上它即可。错误码含义见 **[docs/05-错误码.md](05-错误码.md)**。

Render 自带 Logs 有时延迟，排查优先看这里。

## 7. 计费与额度

本项目不产生额外费用（Render 免费层 + Cloudflare KV 免费额度），消耗的是：

- 你 Google 账号的 Gemini 网页版额度（免费号有频率限制，Pro 更高）；
- Render 免费实例时长（每月 750 小时）；
- Cloudflare KV 每天 1000 次写（本项目统计写已按 5 分钟合并）。

高频使用建议：多账号轮换 + 代理池 + 不要并发轰炸同一个号。
