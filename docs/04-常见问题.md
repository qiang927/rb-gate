# 常见问题（FAQ）

> 先按报错原文搜关键词，再往下看。

---

## 部署与地址

### Q1：我的网址到底是多少？为什么不是 `<用户名>.onrender.com`？

Render 的地址规则是：

```
https://<service-name>.onrender.com
```

- `<service-name>` 是**创建服务时自己填的 Name**（默认等于仓库名）；
- **不包含** Render 用户名、团队名、邮箱；
- 如果名字被占用，Render 会自动加随机后缀，例如 `https://webg-gateway-9x2k.onrender.com`；
- 唯一可靠来源：<https://dashboard.render.com> → 点进服务 → 顶部显示的那一行 URL。

所以：

| 你以为的 | 实际的 |
|---|---|
| `https://<用户名>.onrender.com` | ❌ 不存在这种格式 |
| `https://webg-gateway.onrender.com` | ✅ 前提是服务名就叫 `webg-gateway` 且没被占 |
| `https://webg-gateway-9x2k.onrender.com` | ✅ 名字被占时 Render 自动加的后缀 |

面板地址 = 网址 + `/admin/`；API 地址 = 网址 + `/v1`。

### Q2：改了服务名 / 绑了自定义域名，会怎样？

- 旧 `onrender.com` 地址立即失效，所有客户端要改 Base URL；
- 浏览器里旧域名的登录 Cookie 不会带到新域名 → 需要重新登录（密码不变）；
- 数据不受影响（KV / 磁盘里的凭证、key 都还在）；
- 绑自定义域名不会让旧地址消失，两个都能用；但 Cookie 是两个域，登录状态互不相通。

建议：**尽早绑定自定义域名**，以后所有客户端只认它。

### Q3：访问根路径 404？

正常。根路径只做跳转提示，面板在 `/admin/`（末尾斜杠不能少），API 在 `/v1/...`。

## Cookie 与登录

### Q4：导入时提示 `Cookie 验证失败：…`

按顺序检查：

1. **Cookie 来源不对**：必须是 `gemini.google.com` 的 Cookie。`aistudio.google.com`、`accounts.google.com`、`www.google.com` 的都不行。
2. **用 `document.cookie` 拿的**：`SID`、`__Secure-1PSID` 是 `HttpOnly`，JS 读不到。必须从 DevTools 的 Request Headers 或 Cookie-Editor 导出。
3. **Cookie 已过期**：退出登录/改密码会立即失效，重新导一次。
4. **缺关键字段**：至少要有 `SID` 或 `__Secure-1PSID`。
5. **同一个无痕窗口登录了多个号**：Cookie 可能串，重开无痕窗口只登一个号。

### Q5：`gemini page failed (302) -> https://www.google.com/sorry/index?...`

**不是 Cookie 的问题**，是网关出口 IP 被 Google 风控（机房 IP + 高频探测最常见）。

处理：

1. 面板「设置」→ 代理池 → 导入 Clash 订阅（最有效）；
2. 或设 `WEB_PROXY=http://...` 单代理；
3. 或在 Render 换一个 Region 重建服务换 IP；
4. 或等 1–2 小时风控解除。

### Q6：`gemini page failed (302) -> https://accounts.google.com/ServiceLogin?...`

服务端自己“换出来”的会话不被 Google 认作登录态。本项目已经不支持服务端自动换 Cookie，只支持**浏览器 Cookie 直连**。重新导入一次浏览器 Cookie 即可。

### Q7：导入后能用，过几小时又失效了

网页版 Cookie 本来就会过期（几小时到几天），退出登录/改密码会立即失效。这是预期行为，重新导一次。

如果频繁失效，检查是否有别的设备/插件在清理 Cookie，或该账号是否被 Google 要求重新验证。

## 管理员与登录态

### Q8：登录后点一下又跳回登录页 / 提示 `admin authentication required`

原因通常是：

1. **域名不一致**：`localhost` 和 `127.0.0.1` 的 Cookie 不互通；`xxx.onrender.com` 和自定义域名也不互通。统一用一个地址访问。
2. **免费层刚休眠唤醒**：第一次请求超时，等 30–60 秒刷新。
3. **服务端会话密钥变了**：免费层没配 `ENCRYPTION_KEY`/`SESSION_SECRET` 时，`/data` 清空后会话签名会变 → 旧 Cookie 全部失效，重新登录即可。
4. **密码被改过**：以环境变量 `ADMIN_PASSWORD` 为准（改环境变量会触发重启）。

### Q9：忘记管理员密码了

- 如果配了 `ADMIN_PASSWORD` 环境变量：密码就是它，面板里改不了（会提示由环境变量提供）。忘了就去 Render 改环境变量。
- 如果没配：密码存在 `DATA_DIR/admin.json`（scrypt 哈希，不可逆）。
  - 有 KV：删掉 KV 里的 `webg-gateway/admin` 键，重启后会用环境变量或重新生成；
  - 无 KV：删掉 `admin.json` 重启；
  - 最省事：加一个 `ADMIN_PASSWORD` 环境变量重新部署。

## 模型与调用

### Q10：`model xxx is not available` / `model_not_available`

这个报错通常意味着模型名不在当前账号的 `/v1/models` 里。先看一眼 `/v1/models`：

- 网页版模型按账号 picker 生成：典型 Pro 号是 Auto + 4 Hydrogen（3 档）+ Neon（3 档），共 7 个；Carbon 只在 Ultra 账号出现。形如 `web-gemini-4-neon-high`，不带强度的旧 ID（`web-gemini-4-neon`）等价于 `low`；
- Pro 号请求 `web-gemini-4-carbon-*` 会返回 `404 model_not_available`，不会静默降级；
- 导入 AI Studio Cookie 后还会出现 `pggo-*` 模型（例如 `pggo-gemini-4-neon`），清单以那个账号的 AI Studio 目录为准；
- 旧 ID（`web-gemini-3.7-flash` 等）已删除。

如果 `/v1/models` 里根本没有 `pggo-*`，说明还没导入 AI Studio Cookie，或该凭证已失效。

### Q11：`no web credential: import a Gemini web cookie first`

还没导入 Cookie，或凭证全被禁用/删除了。去「凭证」页导入。

### Q12：`web_failed` / `upstream 429` / 回答到一半断了

- 429：账号或出口 IP 被限流 → 等一会、换节点、加账号；
- 到一半断：代理节点不稳，换节点重试；
- 502：上游报错，面板「日志」里会有完整错误（含 Google 返回的 JSON）。

按 `error.code` / HTTP 状态码逐项排查见 **[docs/05-错误码.md](05-错误码.md)**。

### Q13：为什么网页版模型和别人不一样？为什么不能传图片 / 用工具调用？

- 网页版可选模型由账号 picker 决定（Auto / 4 Hydrogen / Neon，Ultra 另有 4 Carbon）；Argon 是否出现取决于账号，Carbon 需要 Ultra 权益。
- 本项目是“把网页版对话框翻译成 API”，网页版不支持函数调用、图片输入、JSON mode，所以也不支持。
- 需要这些能力 → 用官方 `gemini-4-argon` API。

### Q14：回答质量/速度不稳定

多个因素：账号档位、当前代理节点、Google 负载。可以：

- 「模型 → 刷新目录」看当前账号有哪些模型；
- 「设置 → 代理池」测速并切到低延迟节点；
- 换 `web-gemini-4-hydrogen-low` 换速度。

## 数据与持久化

### Q15：重新部署后凭证没了 / API Key 没了

Render 免费层 `/data` 是临时的。解决：

1. 配 Cloudflare KV（`CF_KV_API_TOKEN` / `CF_ACCOUNT_ID` / `CF_KV_NAMESPACE_ID`），见部署文档；
2. 或付费实例挂持久盘（`render.yaml` 里有 disk 段注释）；
3. 或每次重新部署后手动重导（不推荐）。

### Q16：日志里 `config: ENCRYPTION_KEY not set: a local key file in DATA_DIR is used`

意思是加密密钥来自 `DATA_DIR/secret.key`，在免费层重启后会丢 → KV 里的密文解不开。**必须**在 Render 配一个固定的 `ENCRYPTION_KEY`（64 位 hex）。

### Q17：我换了 `ENCRYPTION_KEY`，之前的凭证全报解密失败

换密钥 = 旧密文全部作废，这是设计如此。重新导入 Cookie 和 API Key 即可。

### Q18：KV 写入会不会超免费额度？

免费额度每天 1000 写。本项目：

- 凭证/API Key 变更：立即写；
- 使用统计（uses）：合并后每 5 分钟写一次；
- 正常个人使用一天几十次写，够用。

如果超了，Cloudflare 会报错，面板日志可见。

### Q19：能把数据备份出来吗

`DATA_DIR` 下的四个 JSON（`credentials.json`、`api-keys.json`、`admin.json`、`settings.json`）就是全部数据；但凭证是密文，备份时连 `ENCRYPTION_KEY` 一起保存才能恢复。

## 风险与合规

### Q20：会被封号吗？

有风险。Google 的服务条款不允许把网页版/客户端会话用于第三方 API 转售或自动化调用，已有封号案例。降低风险的做法：

- 个人自用、低频、不对外分发；
- 不要并发轰炸同一个账号；
- 不要用来做商业转售；
- 重要账号不要用。

**商用请走官方 Gemini API。**

### Q21：能给别人用吗？

技术上可以多发几个 API Key；但这会把你的账号暴露给他人使用，封号风险与费用风险都由你承担。建议只给自己或极少数可信的人用。

### Q22：为什么面板里不能改 Cookie，只能删了重导？

Cookie 是一整串会话，改其中一两个字段没有意义。失效就重新导一条（同邮箱会覆盖旧记录）。

### Q23：「额度」显示 5h 96% / 7d 98.7%，两个账号数字一模一样，是串号了吗？

不是。面板会用每个 Cookie 的 `SID` / `SAPISID` 等身份 Cookie 算一个指纹（日志里的 `fp=`），两个账号的指纹不同就说明会话确实是两份。数字相同通常是因为：

- 两个账号都属于同一个 Google 家庭组 / 共享同一份订阅额度；
- 用量都很低，Google 返回的百分比粒度较粗（例如都落在 4% / 1.3%）；
- 5h / 7d 的窗口边界由 Google 统一对齐（`resetsAt` 一样），不代表账号相同。

如果担心，可以点其中一个账号的「额度」看 `fetchedAt`，并对比日志里的 `fp=`。

### Q24：为什么 4 Carbon 用不了 / 提示 `high demand`？

- 网关不再写死 Carbon。`/v1/models` 里的网页模型来自当前账号 `otAQ7b` 返回的模型选择器（picker）：Pro 号只有 Auto / 4 Hydrogen / Neon，**Carbon 只对 Ultra 开放**。
- 在旧版本里，显式指定 Carbon 不会报错，Google 会**静默降级**成 4 Hydrogen，看起来“能用”，实际答的不是 Carbon。新版本会按账号目录拒绝，返回 `404 model_not_available`。
- 4 Hydrogen / 4 Argon 也可能在高负载时返回 `503 This model is currently experiencing high demand`——这是 Google 侧限流，换时间或换账号重试即可。
- 想看当前账号到底能用哪些模型：面板「模型 → 刷新目录」（会重新读取账号的 picker）。
