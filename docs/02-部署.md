# 保姆级部署：Render + Cloudflare KV

> 目标：从零到“能用 API 调通”，大约 15 分钟。每一步都写了“你应该看到什么”，不对就停下来看第 4 步排查。

---

## 0. 你需要

- 一个能正常对话的 Google 账号（免费号或 Pro 都行）
- 一个 GitHub 账号
- 一个 Cloudflare 账号（只用免费 KV，强烈推荐）
- 一个 Render 账号（免费层就够）

---

## 1. Fork 仓库

1. 打开 <https://github.com/qiang927/rb-gate>
2. 右上角 **Fork** → **Create fork**
3. 此时你的仓库是 `https://github.com/<你的用户名>/rb-gate`

> 仓库根目录就是应用根目录（`Dockerfile`、`package.json` 都在根目录），Render 里不需要填子目录。

---

## 2. 创建 Cloudflare KV（可选，但强烈建议）

Render 免费层的磁盘是临时的：**每次重新部署、休眠唤醒，`/data` 都会清空**，凭证和 API Key 会丢。用 KV 就能持久化。

### 2.1 创建 KV namespace

1. 登录 <https://dash.cloudflare.com>
2. 左侧 **Storage & Databases**（旧版叫 Workers & Pages）→ **KV**
3. **Create a namespace** → 名字随便，比如 `robin` → 保存
4. 进入这个 namespace，记下 **Namespace ID**（32 位十六进制）

### 2.2 记下 Account ID

在 Cloudflare 控制台右下角 / 任意域名 Overview 页右侧，有一串 **Account ID**，复制下来。

### 2.3 创建 API Token

1. 右上角头像 → **My Profile** → **API Tokens** → **Create Token**
2. 选 **Create Custom Token**
3. Permissions：`Account` → `Workers KV Storage` → `Edit`
4. Account Resources：`Include` → 你的账号
5. Continue → Create → **复制 token（只显示一次）**

> token 形如 `cfut_...`。它只能读写这个账号的 KV，不要泄露。

---

## 3. 在 Render 创建服务

1. 登录 <https://dashboard.render.com>
2. **New +** → **Web Service**
3. 连接 GitHub → 选你刚 fork 的 `rb-gate` 仓库 → **Connect**
4. 填写：
   - **Name**：比如 `rb-gate`（这就是以后域名的前缀，见第 4 步）
   - **Region**：选离你近的，比如 Singapore
   - **Branch**：`main`
   - **Runtime**：**Docker**（不是 Node！）
   - **Instance Type**：**Free**
   - **Health Check Path**：`/health`
5. 展开 **Environment Variables**，添加下面这些（键值一行一个）：

| Key | Value | 必填 |
|---|---|---|
| `ADMIN_PASSWORD` | 你的面板密码（≥8 位，自己定） | ✅ |
| `ENCRYPTION_KEY` | 64 位十六进制随机串，点 Render 的 “Generate” 或本地 `openssl rand -hex 32` | ✅ 强烈建议固定 |
| `CF_KV_API_TOKEN` | 第 2.3 步的 token | 可选 |
| `CF_ACCOUNT_ID` | 第 2.2 步的 Account ID | 可选 |
| `CF_KV_NAMESPACE_ID` | 第 2.1 步的 Namespace ID | 可选 |

> **`ENCRYPTION_KEY` 一定要固定**。不设的话网关会在 `DATA_DIR` 里生成一个 `secret.key`，免费层重启后这个文件没了，KV 里的密文就永远解不开了。
>
> 三个 `CF_*` 要么全填、要么全不填。

6. 点 **Create Web Service** / **Deploy Web Service**。

**你应该看到**：部署日志里依次出现

```
store: Cloudflare KV mode (namespace 048158ba…)
gateway listening on port 10000 (credentials=0, dataDir=/data)
```

第一次构建大约 1–3 分钟。看到 `listening` 就成功了。

---

## 4. 找到你的网址（重点，很多人在这里搞错）

**Render 给你的地址长这样：**

```
https://<service-name>.onrender.com
```

比如服务名填了 `rb-gate`，地址就是：

```
https://rb-gate.onrender.com
```

### 一定要注意的三件事

1. **地址里没有 Render 用户名。**
   不是 `https://<你的用户名>.onrender.com`，也不是 `https://render.com/...`，也没有团队名。
2. **`<service-name>` 是你在第 3 步 “Name” 里起的名字**，默认是仓库名（`rb-gate`）。
   如果这个名字已经被别人占用，Render 会自动加一段随机后缀，比如：
   - `https://rb-gate-9x2k.onrender.com`
   - `https://rb-gate.onrender.com` （名字没被占）
3. **以 Dashboard 上显示的为准。**
   打开 <https://dashboard.render.com> → 点进你的服务 → 页面顶部标题下面那一行 `https://....onrender.com` 就是唯一正确的地址。别自己拼。

### 派生地址

| 用途 | 地址 |
|---|---|
| 管理面板 | `https://<你的地址>/admin/`（**末尾的 `/` 不能少**） |
| OpenAI 兼容 Base URL | `https://<你的地址>/v1` |
| 健康检查 | `https://<你的地址>/health` |

服务名可以在 **Settings → Name** 里改，但改了以后：

- 旧地址立即失效，所有客户端要改 Base URL；
- 浏览器里旧的登录 Cookie 对不上新域名，需要重新登录（密码不变）。

> 想以后不再被域名变化折腾：**Settings → Custom Domains** 绑定自己的域名（比如 `api.example.com`），然后把 DNS 的 CNAME 指向 `<service-name>.onrender.com`。之后客户端统一用自定义域名。

## 5. 首次登录面板

1. 打开 `https://<你的地址>/admin/`
2. 输入第 3 步设置的 `ADMIN_PASSWORD`
3. 登录成功后会看到「凭证」「API Keys」「模型」「日志」「设置」几个 tab

**如果登录后又跳回登录页**：

- 确认地址前后一致（`localhost` 与 `127.0.0.1` 的 Cookie 不互通，`xxx.onrender.com` 与自定义域名也不互通）；
- 免费层刚休眠唤醒时，第一次请求可能要等 30–60 秒；
- 确认 `ADMIN_PASSWORD` 没写错（改环境变量会触发重新部署）。

---

## 6. 导入 Gemini Cookie

详细步骤见 [`03-使用.md`](03-使用.md#1-拿到-gemini-网页版-cookie)，简述：

1. 无痕窗口登录 <https://gemini.google.com>，确认能正常对话；
2. F12 → Network → 任意 `gemini.google.com` 请求 → 复制请求头里的整段 `Cookie`；
3. 面板「凭证」→ 粘贴 Cookie →「验证并导入」。

**你应该看到**：凭证池里出现一条 `cookie / active`，点「测试」显示会话有效。

---

## 7. 创建 API Key 并调通

1. 面板「API Keys」→ 新建 → 名字随便 → 复制 `sk-robin-...`（只显示一次）
2. 用 curl 验证（把地址和 key 换成你的）：

```bash
curl https://<你的地址>/v1/chat/completions \
  -H "Authorization: Bearer sk-robin-你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "web-gemini-4-hydrogen",
    "messages": [{"role": "user", "content": "用一句话介绍杭州"}]
  }'
```

**你应该看到**：`choices[0].message.content` 里有一段正常中文。

> 默认不会自动创建 API Key（空列表 = `/v1` 关闭）。必须手动建一个。

---

## 8. 免费层注意事项

| 事项 | 说明 |
|---|---|
| 休眠 | 15 分钟无请求会休眠，下一次请求冷启动约 30–60 秒 |
| 磁盘 | `/data` 临时，重启即丢 → **必须配 KV**，或用付费实例挂持久盘 |
| 带宽/时长 | 免费层每月 750 小时实例时长，够一个服务常驻 |
| 日志 | Render 的 Logs 页有时延迟；面板「日志」tab 是实时的（内存缓冲，重启清空） |

---

## 9. 升级 / 改代码

- 改你 fork 的仓库 → Render 自动重新部署（默认开启 Auto-Deploy）；
- 重新部署后：KV 里的凭证和 key 还在；`/data` 里的东西会没，但因为 KV 优先，不影响使用；
- 如果部署失败：看 Build Logs 第一处红色报错，常见是 Dockerfile 路径或 Node 版本。

---

## 10. 常见部署问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 打开地址 404 | 访问了根路径 | 面板是 `/admin/`，API 是 `/v1/...` |
| 一直 “服务不可达” | 还在构建/休眠中 | 等 60 秒刷新；看 Render Logs |
| 登录又跳回 | 域名不一致 / 密码错 | 统一用一个域名；核对 `ADMIN_PASSWORD` |
| 日志里 `ENCRYPTION_KEY not set` | 没配固定密钥 | 补 `ENCRYPTION_KEY` 后重新部署（旧密文会失效，需重导 Cookie） |
| 部署成功但凭证 0 | 免费层磁盘丢了且没配 KV | 配 `CF_*` 后重新导入 |
| 请求返回 302 `.../sorry/...` | Render 出口 IP 被 Google 风控 | 配代理池，见 [`03-使用.md`](03-使用.md#5-代理池可选但推荐) |

更多问题见 [`04-常见问题.md`](04-常见问题.md)。
